# 05 — DeSciLab paired experience

## Goal

Expose one approved scientific family as a coherent group/personal Insight.

## Build

The catalogue projection gains:

- scientific package/version and paper identity;
- evidence tier, use class, prohibited clinical use, and limitations;
- independently approved `group` and `forMe` execution descriptors;
- reference version and classification/abstention capability.

One detail page shows two plain-language actions:

- **Explore group result**
- **Use my compatible recordings**

Participant/Reown owns personal execution/history. Researcher/Privy owns group
execution/history. Do not join those identities.

Reuse the existing visual renderer and history ownership. Add only the evidence,
paper-classification, reference, and abstention panels required by the new result
contract. A generated example is explicitly labeled and updates only when a new
reviewed example version is published.

## Verification

- Refuse unknown tier/use class, unsafe claim copy, stale reference, mismatched
  mode approval, or a disease label above its evidence tier.
- Participant browser receives no grant/service token/source IDs/cohort details.
- Researcher identity cannot read personal history.
- Complete, privacy-abstained, scientific-abstained, prior-version, and revoked
  states remain distinct.
- Focused Jest, type-check, lint, build, keyboard/chart fallback checks.

## Visual checkpoint

At desktop and 390 px capture:

1. catalogue family and two modes;
2. group result and privacy abstention;
3. personal comparison and scientific abstention;
4. evidence/limitations and immutable version history.

Run screenshot critique. Compare against the current DeSciLab Insight surfaces so
the ReflexDAO visual language is preserved.

## Done when

Both generated modes are understandable without blockchain/Ocean terminology and
all checks pass.
